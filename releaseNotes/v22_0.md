# KLS OneMill — Release Notes
## Version 2.2.0

---

## Graphics Toolbar

### Overlay Toolbar Framework
A new configurable graphics-toolbar overlay renders above the 3D view, similar to Creo Parametric's Graphics Toolbar. Modules contribute toolbar elements through a dedicated provider interface instead of manipulating the toolbar widget directly. The toolbar supports eight placements (corners and edge-centers), horizontal or vertical orientation, per-module and global visibility, and an exclusive mode in which one module's controls temporarily replace all others'.

### 3D Rotation Center Toggle
The View module contributes a checkable "3D Rotation Center" action to the graphics toolbar. Toggling it sets the camera pivot to the current scene's visible center, or clears it; the toggle stays in sync when the pivot is changed another way, such as Alt+middle-click picking in the 3D view.

### Visibility Popup: Groups, Filter, Presets & Saved Sets
The viewport visibility list (the toolbar's eye/visibility button) is no longer a single flat list of ~20 checkboxes. It's now a popup with collapsible groups (Implant, Geometry, Raw Part, Milling), a group-level show/hide toggle, a name filter, four built-in presets (Implant, Milling, Contours, Raw Part), and user-named saved view-sets that can be created, applied, and deleted from the popup itself and persist across sessions. A "solo" action isolates a single item in one click, and Show All/Hide All/Invert act on everything at once.

## Title Bar (Preview)

### Native Title Bar Restructure
The application window now paints its own content into the title bar area while keeping Windows' real native frame underneath — minimize/maximize/close, the resize border, Snap Layout, the taskbar thumbnail, and the drop shadow are all still handled by Windows itself, not recreated. A Quick Access Toolbar on the left carries Load, a split Save button (a caret opens Save As/Reset), and Reset; a "Show on Toolbar" customize menu lets you choose which of these appear, and the choice is remembered between sessions. A single Main Menu button replaces the separate module-switcher, Settings, Help, and Open Log Directory buttons that used to be scattered around the toolbar — switching modules, opening application settings, and each module's own commands (for example "Convert Parameters...") are all reachable from it now, and a module's own commands stay hidden while it isn't the active one. A centered label always shows the application name/version, and — once an implant is open — its file name and status alongside it.

### Screenshot Capture Group
The title bar's Capture group can save either the whole application window or just the render viewport. A default save directory can be set in Settings → View; if none is set yet, the first screenshot prompts once for a folder and remembers the choice for next time.

## Milling

### Multiple Implants on One Raw Part (Preview)
A raw part can now hold more than one implant. Adding a second implant reuses the raw
part, machine, and fixture already chosen for the first instead of selecting a new one;
an implant list lets you add, remove, and switch which implant you're currently working
on, mark one as locked (placement protected from accidental movement) or milled
(a manual status, set once it has actually been machined), and auto-suggest a free
position for the active implant on the shared blank with basic overlap/undercut
checking. Implants you're not currently editing are shown as a simple contour outline
on the raw part rather than disappearing. A raw part can also be reused for a new
session once its implants are removed, keeping its previously machined/occupied areas
in mind when placing new ones.

### Suggest Orientation (Beta)
A new "Suggest Orientation" action sits next to Suggest Position in the implant list. It searches for a base orientation better than simply the flattest one — keeping every detected hole/csys valid while minimizing undercuts and aligning the implant's longest axis with the fixture's main milling direction. Unlike Suggest Position, it only rotates/tilts the implant and never moves it in-plane; it needs a fixture already assigned, and with no holes/csys detected yet it falls back to searching for the flattest undercut-free orientation.

### Toolpath Playback Controls
Displaying a toolpath now shows a dedicated control group in the graphics toolbar: Play, Pause, Restart, a playback-speed selector (0.05×–8×), a seekable progress slider with a percentage readout, a control for how much of the preceding path stays visible behind the current position, a tool-visibility toggle, and a Close button. Displaying a new toolpath reuses the same controls rather than rebuilding them, and positions the tool at the path's start immediately, before playback begins.

### Operations Tree Grouping
The post-generation "Operations" tree is now organized into groups instead of one flat list: Raw Part Marking, Implant Milling, Hole Milling — with its own sub-group per hole — and Strut Removal — with its own sub-group per strut — each collect their own operations together. "Show Toolpath" works on any group, or on the "Operations" tab itself, and plays every operation inside it back to back as one continuous animation, correctly switching to each operation's own tool and orientation as playback reaches it, even when the group mixes tools (for example a hole's drilling and thread-milling passes). Which group an operation belongs to can also be set explicitly on its factory-standard or strategy-template entry, instead of always being worked out automatically.

### Current-Operation Picker & Click-to-Reposition
Displaying a grouped toolpath adds a current-operation selector to the toolbar, showing which operation is playing and letting you jump straight to a different one without changing whether playback is running or paused. A new "pick position" toolbar button lets you click any point directly on the drawn toolpath in the 3D view to move the tool there — handy for nudging the position after pausing a moment too late.

### Configurable Strut Milling-Side Defaults
The mill-bone-side, mill-opposite-side, and curve-add-offset values assigned to a newly created strut are now configurable per factory-standard template instead of fixed. The Peek, Titan, and Titan-Simple templates configure both mill sides on with a 1.5 offset; other templates keep the previous defaults unless they opt in.

### Strut Milling End-Height Scales With Strut Size
A strut's milling end-height can now be calculated automatically from that strut's own diameter (or height, for a rectangular strut) instead of always using one fixed value regardless of the strut's actual size. The VHF Plastik strut template uses this for its end-height.

### Raw Part Marking (Preview)
A round raw part can now be engraved with division lines (thirds, quarters, or a half line), small position-indicator marks next to each line, and the raw part's own name/number — configured from the raw part section of Input Settings and generated together with the first implant milled on that plate. Because the marking belongs to the physical plate rather than to any one implant, it's only ever cut once: the first implant generated on a raw part claims and engraves it, and any further implants added to the same plate skip it. Each position-indicator mark can be cut as either a small engraved circle or a short drilled mark. A live preview shows the planned lines before generating and switches color once they've actually been cut, so a reused plate's real engraving is never mistaken for a not-yet-cut plan. Saving a raw part to the library carries its marking status along, so reloading a previously marked plate for reuse correctly shows what's already been engraved on it. A fixture can optionally define a reference point the marking's first line orients itself toward; when one is set, the plate's re-chuck rotation control only allows the discrete positions that keep the pattern aligned with that reference, instead of any arbitrary angle.

### Tree Context Menu Cleanup
The session tree's "Show" and "Hide" context-menu entries have been merged into a single toggle reflecting the item's current visibility, instead of two entries where only one was ever enabled. Individual toolpath entries no longer show a generic Show/Hide at all — "Show Toolpath" and the new graphics-toolbar Close button are the correct actions for those.

### Compact Input Settings & Extended Settings Panels
The Input Settings panel's session-wide fields (Region/Material/Machine/Fixture), the raw part, and the per-implant work-piece fields each collapse to a single summary line and expand on click, freeing up vertical space — the raw part group's summary shows its current dimensions, and the work-piece group's shows the implant's file name and detected base shape. Extended Settings' strut and window/offset fields are collapsible the same way, and its action buttons (Add Manual Strut, Generate EdgePlanes, Detect Holes, Remove Detected Holes) now sit together at the top of the panel instead of split across two rows further down.

### Tilt Lines Settings Only Shown When Needed
Extended Settings' Tilt Lines group (5-axis tool-tilting sampling parameters) is now hidden unless the currently assigned strategy actually uses line-based tilting, instead of always being shown regardless of whether any of its settings apply. Its debug-only "Test" button has also been removed.

### Loop Placement for Struts
A new "Loop" option next to AddManual Strut keeps the tool armed after each strut is placed, so several can be added in a row without reselecting the button each time. Cancel at any point with Esc or a middle-click.

### Multi-Select Struts
Struts can now be Ctrl+click selected in groups, the same way holes and IGES geometry already could. Right-clicking a multi-selected strut opens the usual edit panel for the whole group at once — shape, orientation, dimensions, and milling strategy assignment all apply to every selected strut on OK — and Remove Strut deletes the entire selection in one go instead of one at a time.

### Raw Part Reuse Improvements
"Suggest Position" now correctly avoids the space already occupied by implants that were on a reused library raw part, instead of treating it as free. A new Reset button clears a reused plate's reference outlines if you decide not to use it after all. Saving a raw part that's already in the library now asks whether to update the existing entry (keeping its outline history) or save it as a separate new one, instead of always silently overwriting it.

### PMMA Material
PMMA is now available as a material type alongside Titan, Peek, and MultiPurpose.

### Manufacturing-Material Selection for MultiPurpose Machines
A machine can be set up as "MultiPurpose" to cover more than one real material. Selecting one now shows an extra "Manuf. Mat." field in Input Settings to say which material is actually being milled this session — it's remembered for next time, and the material shown elsewhere folds "MultiPurpose" into the chosen material instead of showing both. The raw-part library browser can also filter by material, shown as its own column, and pre-selects the current session's material when opened.

### Open Milling Templates: Automatic Window Bulging (Preview)
A hole/csys with an active Open Milling Template (a cone-shaped pocket) now bulges the milling window and its surface outward around that pocket automatically, picking whichever raw-part face actually faces the tool for a given pass, instead of needing a manually placed window curve to clear it. Currently wired up in the sample VHF Plastik roughing passes for testing.

### IGES Milling: Multiple Gauge Checks (Preview)
An IGES milling pass can now run several independent collision-safety checks instead of just one, each guarding its own chosen surface and its own set of tool parts (flute/shaft/arbor/holder). One of these checks can restrict itself to the raw part's own surface that's still unmachined and still facing the tool, so previously-cut areas aren't mistaken for solid stock. Demonstrated in the sample "RoundHoleIges" roughing pass.

### VHF Native-Code Holes (Preview)
A hole or csys can now be assigned an existing, pre-posted toolpath file instead of building one from a drilling curve — currently supported for round and orientated VHF sample holes. The file is positioned onto the hole the same way the geometry and rotation of any other factory-standard template are, and validated directly by the milling module rather than routed through post-processing.

### VHF WN Thread Holes (Preview)
The VHF sample machine can now mill two Werksnorm round thread holes end to end from IGES geometry — WN1716, and the newly added WN1094 — each running a roughing and finishing pass over the hole's drilling curve, a chamfer pass over its offset fase surface, and a final thread-mill pass to clean the thread up afterward. Both holes are wired for the Plastik and Titan material variants, swapping only the roughing/finishing tool between them.

### Hole/Csys Angle Tolerance per Fixture
How far off-axis a hole or csys is allowed to be before it's flagged as unmillable is now configurable per fixture, and a fixture can combine several such checks instead of just one. Every existing fixture keeps its previous single 90° tolerance; the VHF round fixture now checks two directions independently — a stricter 30° one way, a still-unrestricted 90° the other — instead of one uniform 90° in every direction.

### Hole Surfaces (Preview)
Each detected implant hole now gets its own flat cap surface generated alongside the existing milling geometry, and its boundary contour is shown in the 3D view as a thinner line than the implant's outer contour so it reads as a distinct, smaller feature. A milling template entry can reference these hole surfaces as its working geometry the same way it already can the center, height, contour, or bottom surfaces.

## Post Processor

### VHF Subprogram Holes (Preview)
VHF machine output can now reuse a pre-posted hole program for round and orientated holes instead of posting each one from scratch, positioning it onto the target hole and removing a resulting duplicate tool call where the main program had already selected the same tool. Selecting a job-instruction file directly in the Post Processor module now also auto-selects the matching machine.

### Creo NCL Import (Preview)
A new "Import Creo NCL..." button converts a milling feature exported from Creo (an `.ncl` file) into a real, postable VHF `.nc` program next to it, reusing the same machine kinematics and output formatting the module already uses for its own toolpaths. Arc moves and multi-axis mode markers in the imported file are both supported.

## Bug Fixes

### Crash Sending a File After Standby
If the file transfer connection couldn't be established — for example right after the computer woke from standby, before the network was fully back up — the application terminated instead of reporting a failed transfer. The connection attempt is now handled like any other transfer failure.

### Toolpath Animation Trail Sometimes Missing
Seeking, restarting, or changing the visible-history setting while a toolpath animation was displayed could permanently stop the path trail from being drawn for the rest of the session, while the tool actor kept moving normally. A rebuild step was shrinking the underlying draw buffer in a way that broke the incremental drawing used during normal playback; the buffer now stays at full size across every rebuild path.

### Tool Position Not Updated When Seeking
Dragging the toolpath animation's progress slider moved the drawn path trail but left the tool actor at its previous position. Seeking now repositions and re-orients the tool to match the sought position, the same as normal playback does.

### Shutdown Crash During Application Close
Closing the application could occasionally crash inside Qt's Windows platform integration during final process cleanup. A module-owned toolbar widget was only being detached — not destroyed — when its toolbar closed, leaving it to be destroyed much later during plugin unload, after Qt's platform integration could already be torn down. The widget is now destroyed explicitly and early, while the application is still fully running.

### Implant Positions Corrupted When Dragging a Different Implant
With more than one implant in a session, dragging one implant's position could, in certain cases, corrupt the stored position of a different implant that wasn't even being touched. Repositioning now always commits to the implant actually being displayed on screen, not whichever one happened to be the "active" one.

### IGES Milling Preview Not Following Implant While Dragging
The IGES milling preview elements stayed in place instead of moving with the implant during live repositioning; they now update together with it.

### Crash Selecting a Machine/Fixture With No Matching Raw Part
Selecting certain machine/fixture combinations could crash the application instead of showing an error when no matching raw part was found for them.

### Action Buttons Disabled After Swapping to a Reused Raw Part
After loading a raw part to reuse an existing plate on a session that already had implants, buttons like Assign Implant Position, Refresh, and Geometry became disabled even though the implant was still there and workable. They now stay enabled as expected.

### Toolpath Progress Briefly Reading Over 100%
The toolpath animation's percentage readout could read slightly above 100% (e.g. 102%) once playback reached the end, while the slider itself still stopped correctly at the end position. The underlying calculation is fixed so it can no longer exceed 100%.

### Raw Part Marking Cut After the Implant Instead of Before
Generating the toolpath cut the raw part's marking (division lines/text) after the implant's own milling instead of before it, even though the marking is meant to be engraved onto the untouched plate first. The marking now always runs first, ahead of any implant milling.

### Raw Part Dimensions Not Updated After Reusing a Library Raw Part
Loading a previously-saved raw part from the library could leave the session showing (and milling against) the wrong plate thickness/width/height — the values from before the swap kept silently overriding the reused plate's real dimensions, and the Input Settings panel never refreshed to show them either way. Reusing a raw part now always reflects that plate's actual dimensions.

### Crash Generating After Reloading an Already-Generated File
Loading a .klso file that had already been through a full toolpath generation before saving, then pressing Geometry followed by Generate, could crash instead of regenerating. Reloading restored the on-screen generation progress without rebuilding the in-memory geometry data that step depends on; pressing Geometry now rebuilds it correctly whenever it's missing, instead of assuming it's already there.

### Graphics Toolbar Overlay Not Resizing for a Module's Own Content Changes
A module's graphics-toolbar controls could end up squeezed into too little space when something inside them changed size on its own — for example, the toolpath toolbar's current-operation selector appearing — while the toolbar group itself stayed visible the whole time. The overlay previously only resized to fit its content on a window resize or when a whole module's group was shown or hidden; it now also resizes when a module explicitly requests it after changing its own controls.

### Module Failed to Load on Some Computers
On some computers, the milling module could fail to load entirely at startup — the rest of the application still worked, but every milling feature was missing for that session, with no clear indication why. This happened when an optional startup check hit a drive that exists but isn't ready (for example an empty optical drive, or a disconnected/sleeping removable drive) rather than one that simply doesn't exist; the check no longer treats the two cases the same way.

### Custom Title Bar Left the Window Unclosable on Some Windows Setups
On some Windows environments — for example a Windows guest running inside Parallels on a Mac — the application's custom-drawn title bar could render, but its minimize/maximize/close buttons stopped responding entirely, leaving no way to close the window from the title bar. The application now falls back to a normal, always-functional native title bar automatically when the Windows feature the custom one depends on isn't fully available, instead of assuming it always is.

### Window Could Not Be Moved by Dragging the Title Bar on Scaled Displays
On a display scaled above 100% (common for a Mac's Retina display run through Parallels, but possible on any scaled Windows display), dragging the title bar to move the window silently did nothing, even though the minimize/maximize/close buttons kept working normally. The title bar's drag-area detection was using un-scaled coordinates on scaled displays; it now uses the same correctly-scaled coordinates the buttons already did.

### Raw Part or Overlay Markers Sometimes Invisible as if Clipped
Parts of the raw part, or an on-screen marker like the implant's lock/selection-blocked indicator, could occasionally disappear as if cut off by an invisible wall near the camera, most noticeable on some graphics setups. The camera's visible depth range was being calculated from only one of two overlapping render layers that actually share a single camera; it's now calculated from both together.

### Lock/Selection-Blocked Marker Sometimes Missing on the Implant
Clicking a locked implant (one whose geometry has already been generated) is meant to first show a circular "selection blocked" marker requiring a confirming second click, rather than selecting or moving it immediately. That marker could fail to appear at all after the implant's display was refreshed or switched, silently allowing the implant to be selected/moved directly again even though it was still supposed to be locked. The lock state is now correctly re-applied every time the implant's on-screen display is rebuilt.

### Stray Tiny Faces Included in a Finishing Pass's Collision Check
A finishing (Schlichten) operation's collision check against the raw part's own previous top surface could pick up tiny stray slivers of mesh inside the contour area that shouldn't have counted as that surface at all, left over from an earlier pass. That surface search now ignores any such patch below a configurable minimum size (2mm² by default).
